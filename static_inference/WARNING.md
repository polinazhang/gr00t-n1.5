GR00T-N1.5's own forward path never passes image_flags either (EagleBackbone.forward_eagle sends whatever the eagle processor emits minus image_sizes — i.e. input_ids, attention_mask, pixel_values; the processor emits no image_flags). The image_flags machinery exists inside Eagle2_5_VL.forward but is dead code in this entire codebase. So our static path matches the model's real training/inference semantics exactly — which is what the loss-equivalence requirement demands. If masked inputs were introduced someday, the original GR00T pipeline would have the same gap, and "match the original loss semantics" would then conflict with the masked-image note.
